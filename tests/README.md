# 测试标准

测试保护玩家命令、实物和资金结算、取消回收以及存档安全，不为每个内容条目做验收。
同样的机制换一种配方、名称、数值或画法，测试不应因此增加或失效。不要为了通过测试改变玩法或诱导自主决策。

## 运行

默认运行四组机制回归：

```sh
godot --headless --log-file /tmp/law3-tests.log --path . --script tests/run.gd
```

单组在末尾追加 `-- --suite=world`，也可选择 `production`、`equipment`、`interaction`。
检查失败返回非零退出码；还须检查日志没有 `SCRIPT ERROR` 或 `ERROR:`，不能只看最后一行。

输入相关修改运行同一套原生窗口回归，期间不要移动鼠标或切换窗口：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-native-tests.log --path . --script tests/run.gd -- --suite=interaction --native
```

交互组只保留命令接线与代表性拾取。原生截图为 `/tmp/law3-input-world.png`、`/tmp/law3-input-blueprint.png`、
`/tmp/law3-input-research.png`、`/tmp/law3-input-research-complete.png`、`/tmp/law3-input-tools.png`、`/tmp/law3-input-wage-details.png`、`/tmp/law3-input-wages-{1440,960}.png`、`/tmp/law3-input-fee-details.png`、`/tmp/law3-input-fees-{1440,960}.png` 和 `/tmp/law3-input-rebased-{1440,960}.png`，用于检查实际点中位置、遮挡和坐标转换。
无窗口通过不代表 OS 窗口的输入通过。素材、动画、排版和说明文案在实际游戏中人工观察，不建立自动展示验收或逐内容截图目录。

地图总览仍是按需的人工观察工具，不计入默认回归，也不检查种子、资源目录或各矿种点击：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-map-preview.log --path . --script tests/run.gd -- --generated-map --native
```

预览使用三个固定种子，输出 `/tmp/law3-generated-map-{seed}-{1440,960}.png` 和营地截图。

## 模块边界

| 文件 | 职责 |
| --- | --- |
| `run.gd` | 参数、启动、套件选择、汇总和退出 |
| `support/fixtures.gd` | 合法的初始地图、资源、设备和人口；不伪造执行中的活动 |
| `support/context.gd` | 断言、有界等待、报告与实物观察 |
| `support/viewport_input.gd` | 鼠标和键盘事件、窗口等待与代表性输入截图；不包含结果断言 |
| `world_behaviors.gd` | 开采、建造承诺与逐件供料、任务专用库存的取消和续接、取消回收、多件上带与入口等待、物流和借贷结算、报告、重置、快照续接与文件完整性 |
| `production_behaviors.gd` | 日产与有限订单、已投入批次、跨日、实际供料、竞争接收、供电耗料、科研切换和最后一点结算 |
| `equipment_behaviors.gd` | 代表性商品与服务的库存转移、实际收费、消费和耗尽，以及就医与运输交叉、生理极限硬打断与恢复后的物资和付款安全 |
| `interaction_behaviors.gd` | 选中目标、下单、取消、生产和科研控制、搬迁、存档操作、UI 拦截与远坐标输入 |
| `diagnostics/map_preview.gd` | 按需地图总览，不执行内容验收 |

套件不相互实例化；共享的起点、输入驱动和观察方法放在 support。
普通业务夹具可从已解锁科技的世界开始；科研夹具使用合法的前置和初始进度。夹具不代表出生规则或理想作息。

## 不再承担的职责

- **全品类内容验收。** 不遍历全部建筑、产业、装备和矿种逐项运行完整模拟，也不为每条产业链另做一轮端到端验收。新增配置不自动增加测试；只有不同的执行机制或具体回归才增加案例。
- **平衡数值实验。** 不维护心情与装备的效率比较、污染暴露曲线、疲劳恢复、食堂恢复测量、增益倍率与持续时间实验，不把当前初版数值或自主活动倾向固化为测试合同。
- **展示验收。** 不检查飘字、缺料动画、效果提示、描述字段、图表排版、逐控件几何边界或素材图鉴。选中谁、命令是否生效、界面是否拦住世界输入仍属于交互契约。
- 不验证 Godot 的通用节点、信号、控件、排序或布局机制。
- 不把生活节奏、指定执行者、活动顺序、固定休息次数或生活达标当作通过条件；不反复调整需要、现金或心情来强迫预想选择。

## 保留的契约

1. **玩家命令。** 从合法起点下达实际命令，再推进有界游戏时间；不能通过改写活动、路径、任务进度或归属令任务完成。
2. **实物和付款。** 未到货不能消耗，未完成不能产出；运输、买卖与工资只转移所有权，消费和投入才减少库存。不能重复收费、透支、重复交付或丢失货物。
3. **取消与中断。** 只回收实际物资，不退还未满足的配方；保留已经结算的劳动，不重复发工资或复活已取消的指令。
4. **机制代表。** 混合配方代表建造结算，普通加工代表日产；多阶段生长、有限人口订单、屠宰和科研分别覆盖不同生命周期。放置只按普通占地、矿石清场、水源限制和线状设施等机制选代表，不按完整内容目录扩张。
5. **物理限制。** 保留完整占地、可达性、已预约运输、竞争接收、线路容量、断线和改接目的地的实际结果约束，不以简化测试为理由更改游戏中的这些保障。
6. **存档安全。** 按不同保存内容各取一个有意义的检查点，验证恢复不增减货物和款项、未完成命令可继续、已投入材料不重复扣除；重复恢复只验证一次，坏档不能替换当前世界或损坏健康备份。
7. **输入接线。** 使用真实 Viewport 事件验证选择、下单、取消、HUD 拦截和坐标重定位；同一条输入路径不按商品、工具、缩放和窗口尺寸做笛卡尔积。
8. **不掩盖失败。** 区分规则错误、无效夹具和越界预期，不为凑绿灯改变工人决策或删除仍在范围内的资金、物资安全检查。架构约束由代码审查保证。
