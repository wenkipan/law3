# 测试标准

测试验证游戏规则和本项目的接线，不验证 Godot 本身，也不规定小人应该怎样生活。
同样的玩法换一种实现，测试应该仍然成立。不要为了通过测试而改变游戏规则或诱导自主决策。

## 运行

默认运行四组功能回归：

```sh
godot --headless --log-file /tmp/law3-tests.log --path . --script tests/run.gd
```

单组运行在末尾追加 `-- --suite=world`；也可选择 `production`、`equipment`、`interaction`。
检查失败返回非零退出码。还须检查日志没有 `SCRIPT ERROR` 或 `ERROR:`，不能仅凭最后的 PASS 判断成功。

输入或显示相关修改再运行原生窗口测试。期间不要移动鼠标或切换窗口：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-native-tests.log --path . --script tests/run.gd -- --suite=interaction --native
```

窗口模式保存截图到 `/tmp/law3-*.png`。重点检查两个窗口尺寸下的详情、工具栏、报告、蓝图、运输和远坐标画面。
截图用于人工检查素材、文字裁切和遮挡，不做自动图像比对；无窗口通过不代表原生输入或画面通过。

地图总览单独按需运行，不混入日常交互回归：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-map-preview.log --path . --script tests/run.gd -- --generated-map --native
```

地图预览使用三个固定种子，输出 `/tmp/law3-generated-map-{seed}-{1440,960}.png`。
生成比例、探索顺序与挖掘后不刷新矿石仍由世界组验证。

## 模块边界

| 文件 | 职责 |
| --- | --- |
| `run.gd` | 参数、启动、选择套件、汇总、退出 |
| `support/fixtures.gd` | 初始地图、资源、设备和人口夹具；共享材料运输样本 |
| `support/context.gd` | 断言、有界模拟等待、报告和可见货物观察 |
| `support/viewport_input.gd` | 真实鼠标和键盘事件、窗口等待、截图；不包含游戏结果断言 |
| `world_behaviors.gd` | 地图与探索、开采、蓝图材料承诺、供料、取消回收、运输、劳动及借贷结算、报告和重置 |
| `production_behaviors.gd` | 配方、日产量与有限订单、停产及跨日、供电耗料、实际工资、设施效果和库存守恒 |
| `equipment_behaviors.gd` | 实际交易价格、库存与付款、装备使用效果和耗尽 |
| `interaction_behaviors.gd` | 玩家点击与拖放、详情更新、工具禁用、HUD 拦截、坐标转换和代表性布局 |
| `diagnostics/map_preview.gd` | 按需生成地图总览，复用同一夹具与输入驱动 |

套件之间不相互实例化。共享夹具、输入驱动和观察方法放在 support，不复制游戏生产、结算或决策逻辑。
新增规则优先扩展现有套件和参数表，不为每个建筑或修复新增测试脚本。

## 不测什么

- 不把五天生计、每日收入、温饱、睡眠次数或闲暇安排当作通过条件；不保留节奏校准模式。
- 不要求某个工人先工作再进食、一定租床、优先选近岗位或便宜店铺，也不要求新人出生后立即劳动。
- 不通过反复调整饱食、疲劳、余额或心情来让预想的选择必然发生；不改写活动、路径、任务进度或归属。
- 不验证 Godot 通用按钮、信号、节点类型、对象身份、引擎拾取排序或容器布局机制是否正确。
- 不重复穷举“每种建筑 × 每个工具 × 每档缩放 × 每个窗口尺寸”。

世界组不是生活模拟验收。小人的自主选择不是测试脚本的指令；测试只对玩家命令的结果和实际发生的行为负责。

## 保留什么

1. **合法起点。** 夹具可以描述初始资源、装备、身体需要、位置和已有设施，但不能伪造正在执行的动作。业务夹具不代表出生规则或理想生活节奏。
2. **实际命令。** 下达挖掘、建造、取消或生产命令后推进模拟。集成用例可以有界等待产物或交易以检查功能，但不能指定执行者、活动顺序或把等待上限当作作息规则。
3. **结果约束。** 检查实物、付款、产物、恢复效果、人数和报告。未到货不能消耗，未完成不能产出，取消只回收实物，交易与工资不能凭空创造物品。
4. **参数化差异。** 全部建筑共用配方、供料与回收契约；输入仅覆盖不同放置路径、占地和限制的代表。新品种加入相应数据表，不重跑一份相同点击流程。
5. **具体回归。** 每个案例说明要防止的玩家损失，例如重复扣料、取消后继续施工、改接矿道错送。没有独立规则或风险的重复案例删除。
6. **本项目的 UI 接线。** 原生事件用于验证点中的详情、建材禁用、拖放命令、HUD 不穿透及远坐标不选错对象，不断言节点树、信号次数或贴图文件名。
7. **有界等待。** 按业务结果等待，不依赖机器快慢或某一帧内部状态。精确时间比较仅用于明确的工时或恢复规则，排除选择、通勤和休息时间。
8. **不掩盖失败。** 失败后先区分规则错误、夹具无效和测试越界；不能为凑绿灯改变工人的决策。架构约束由代码审查保证。
