# 测试标准

测试要回答“玩家做了什么，最后得到了什么”，而不是证明当前实现长什么样。
同样的玩法换一种实现，测试应该仍然成立。不要为了减少测试而改动游戏规则。

## 运行

日常只运行一个入口（失败返回非零退出码，并显示场景与失败结果）：

```sh
godot --headless --log-file /tmp/law3-tests.log --path . --script tests/run.gd
```

定位问题时可在末尾加 `-- --suite=world`，也可选择 `production`、`equipment`、`interaction`。
所有等待都有游戏时间上限，不依赖机器快慢，也不使用无限等待状态的循环。

复查“很饿但仍闲逛”时，沿用世界组的独立诊断模式：三个工人初始饱食度 0、疲劳 30，发布 600 个砂岩挖掘指令和三张缺料床蓝图，连续模拟五天，不额外注入材料或工资，不强制派工。它输出每日库存、进餐、付款和劳动报告；检查通过不代替分析闲逛日志。

```sh
godot --headless --log-file /tmp/law3-mining-beds-5days.log --path . --script tests/run.gd -- --suite=world --hungry-audit --trace-ai --trace-ai-max-mib=64 --trace-ai-file=/tmp/law3-mining-beds-5days.jsonl
```

日志的 `diagnostic/hungry_idle` 表示饱食度小于 20 时实际进入闲逛，含工作、进餐、领工资与闲逛分数、阻断原因。用同一工人的 `decision` 对照 `utility/evaluated` 完整候选；不要把设施数量当成有效订单，也不要把缺钱、缺料、不可达或岗位被占用混为评分问题。`test/scenario` 和 `test/observation` 标记起点与每日可观察结果。全候选日志较大，此命令把单文件上限提高到 64 MiB，避免默认轮转覆盖开头；默认上限仍为 8 MiB。

修改交互或显示时，再跑同一套交互测试的窗口模式。期间不要移动鼠标：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-native-tests.log --path . --script tests/run.gd -- --suite=interaction --native
```

生产组覆盖任意电线直连、混线容量瓶颈、人力发电实际工资与断路、日光灯工资和还款守恒，以及食堂抢座、不可达、距离、跨日、不同食量与座位释放。装备组对矿枪、背包、清水使用同一价格契约，验证溢价、不叠加、断电、范围、便宜店铺与挣取差价，不断言内部预算或任务状态。

电线沿用交互组的成排建造场景，另存 `/tmp/law3-power-{high_line,low_line}-{horizontal,vertical}-{preview,building,branch}.png`
及同名前缀的 `-{1440,960}.png`。检查金色高压双线、青色低压细线、转角与分支连接、蓝图逐步显形、双尺寸缩放和工具栏图标；拆除分支不能误拆主线。

随机地图总览使用种子 `0`、`1020`、`4294967295` 的实际 256 × 192 格区域，截图为 `/tmp/law3-generated-map-{seed}-{1440,960}.png`，种子 1020 同时保留 `/tmp/law3-generated-map-{1440,960}.png`。检查砂岩主体、不同大小和轮廓的矿斑、洞室、水源与点击详情对应。世界组打印这三个区域的实际砂岩比例，并验证在 75%～80% 之间；不要求每个小区块恰好达到此比例。其他业务场景使用明确的砂岩采场、水源和出生空地夹具，不依赖随机开局是否适合建造。

只复用地图总览及矿物点击场景时，在交互组命令末尾追加 `--generated-map`；加 `--native` 可输出上述截图，不另设视觉脚本。统计通过不代替人工审查地图分布。

无限地图沿用 `world` 与 `interaction`：检查远处正负坐标的地形复现、反向探索顺序、自然空洞和单格特殊资源，以及旧地图边界外和 `(-1, -1)` 的实际采矿交付。交互组在负坐标、旧边界外和 `(65536, -65536)` 检查镜头重定位后的地形、建筑、工人拾取、缩放、HUD 拦截、返回原地、框选和蓝图放置；移动镜头不能探索或在迷雾中建造。窗口模式另存 `/tmp/law3-streamed-map-{1440,960}.png`，检查远坐标素材与悬浮框没有错位或截断。

## 四组行为

| 文件 | 结果契约 |
| --- | --- |
| `world_behaviors.gd` | 采矿交付与取消；全部建筑缺料规划、指定配方、实物供料、完成消耗、取消回收、先挖后建和等待通路；占地内外新矿直送、生产直供、多人争料、混装背包分送、在途防重复和取消改送；矿道直接卸货、汇流、断线恢复、归属和运费；生活需求与床位；借款差额、还款和本金/利息收支；跨日报告、暂停、速度与重置 |
| `production_behaviors.gd` | 日产量跨天保留、停产与缺料；睡眠和午夜中断接续；本地原料竞争、人工与轨道运输；库存守恒；农田三阶段与重复耕种；输电容量、实际耗煤、停电与无人值班；灯光和喷泉不叠加、每日补水；致密矿重复产出、取消和矿钻搬迁；电力运输断电保货；打印有限订单和新人工作 |
| `equipment_behaviors.gd` | 交易不能超卖；卖出不补当日配额；矿枪确实更快、饮水确实减疲劳；背包双块交付、耗尽、半载返回 |
| `interaction_behaviors.gd` | 真实点击、缩放和遮挡；UI 拦截；蓝图完成后详情连续；全部建筑成排拖动、占地间距、轴向锁定与鼠标取消；矿道拖动、转弯、反向重连、拆除及载货保护；日产量控件、新人选择与窗口布局 |

`run.gd` 只负责启动、初始场景、有限等待、结果检查和输入事件，不替游戏实现生产或决策。

状态树迁移沿用这四组。`world` 额外验证欠债时少量进食、距离改变真实工作选择、多人争床以及饮水中取消后继续新命令；检查食物、付款、产物和报告，不断言私有活动或预留字段。日常需求不再按旧每日预算门槛断言，等待使用有界结果条件，不能为了尽快完成而强制改写执行状态。

`production` 另用真实供电的日光灯验证工资改变首先完成的订单，以及开工后断灯不改变已锁定的批次报酬；用两台矿钻竞争同一矿点验证不能同时加速开采、不能重复出货，取消后仍可继续新命令。检查日志中没有 `SCRIPT ERROR`，不能只看最终检查数量和退出码。

劳动结算沿用 `world` 的三类劳动与取消、换人场景，验证效率只改变工期、不改变任务报酬；未完工不逐步付款，中断只支付真实完成份额，换人总报酬不重复，未完成产物不提前生成。`production` 共用发电机参数表验证完整一小时周期结算与断线后的部分周期结算；等待开工使用实际劳动报告，不再用“第一笔工资”代表开工。分数份额允许作为食物使用，库存与真实付款继续守恒。

心情沿用现有三组：`world` 检查劳动速度、实际工资、床睡余韵和免费恢复；
`equipment` 检查可选购物、食物与工具保障、不可达和缺货、不扩大借款；
`production` 检查实际舒适用餐、喷泉不叠加、机械劳动经历与恢复，以及低心情时仍可完成劳动；
同组参数化环境场景检查发电、钻探和自动运输仅在实际运行时干扰附近睡眠，
以及断电、缺燃料、静止积货、距离、不叠加、用餐体验与身体恢复不变。
初始心情可作为需要夹具设置；断言心情恢复、产出、付款和报告，不读取或写入私有回避计时与决策标签。

## 写法约定

1. **先安排起点，再操作，最后观察。** 初始资源、装备、疲劳、位置、已有建筑可以由夹具设置；操作必须走实际命令和模拟。不要直接写 `state`、`progress`、`owner`、路径或任务字典来制造中断、完成、交付。
2. **只断言有玩法含义的结果。** 库存、余额、产量、疲劳、使用次数、人数、报告、详情文字可以直接读取。它们虽存放在字典中，但代表玩家能观察的结果；并不要求所有逻辑测试都用鼠标操作。
3. **不锁定实现。** 不检查预算计算过程、调度状态名、任务归属、缓存命中、节点类型/身份、信号数量、贴图文件名。不直接调用 `assign_job`、`start_sleep` 等内部决策方法。入口是玩家命令、`simulate` 时钟或用于验证暂停/速度的引擎帧回调；UI 绑定和夹具允许知道少量结构，不能借辅助函数把实现断言藏起来。
4. **同一规则只维护一份。** 各类建筑共用规划与实物供料规则、各类生产共用日产量规则，用参数表覆盖差异。新品种优先加入现有表，不再复制整份测试和截图脚本。
5. **优先完整流程与关键失败路径。** 一项新规则通常补一个正常流程，加最有风险的边界，例如不足、取消、跨日、争抢或耗尽。不是每个分支都要一条测试；不以数量、行覆盖率或断言数作为目标。
6. **回归必须能说出玩家损失。** 例如“两个净水器把同一批水用了两次”，而非“任务 owner 错误”。新增回归尽量复用现有场景，保留能够区分正确与错误结果的断言。
7. **时间按业务结果等待。** 使用有上限的模拟时间等待交付、生产或购买；不要绑定某一帧的中间状态。只有规则本身涉及金额、时长或比例时才精确比较，并注明必要容差。
8. **界面测交互与可见内容。** 点击由 Viewport 分发，不用直接发按钮信号代替拾取测试。检查选中详情、控件禁用、布局边界，不要求具体节点树。不可用布局通过来替代人工画面检查。
