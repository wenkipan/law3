# 测试标准

测试保护玩家命令、实物和资金结算、取消回收以及存档安全，不为每个内容条目做验收。
同样的机制换一种配方、名称、数值或画法，测试不应因此增加或失效。不要为了通过测试改变玩法或诱导自主决策。

## 运行

默认运行四组机制回归：

```sh
godot --headless --log-file /tmp/law3-tests.log --path . --script tests/run.gd
```

单组在末尾追加 `-- --suite=world`，也可选择 `production`、`equipment`、`interaction`。
检查失败返回非零退出码；还须检查日志没有 `SCRIPT ERROR` 或 `ERROR:`，不能只看最后一行。

输入相关修改运行同一套原生窗口回归，期间不要移动鼠标或切换窗口：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-native-tests.log --path . --script tests/run.gd -- --suite=interaction --native
```

交互组只保留新经营循环的命令接线与代表性拾取。原生截图为 `/tmp/law3-input-world.png`、`/tmp/law3-input-blueprint.png`、`/tmp/law3-input-blueprint-delivery.png`、
`/tmp/law3-input-market.png`、`/tmp/law3-input-market-960.png`、`/tmp/law3-input-fog.png`、`/tmp/law3-input-player-build.png` 和 `/tmp/law3-input-player-items.png`，用于检查实际点中位置、市场报价、关闭控件、遮挡、迷雾及手动建造与拖运。
无窗口通过不代表 OS 窗口的输入通过。素材、动画、排版和说明文案在实际游戏中人工观察，不建立自动展示验收或逐内容截图目录。
市场蓝图截图用于人工检查同一个需求气泡：实物离开货源但尚未送达时保留需求，部分到货后减少，备齐且可施工后切换为施工图标。不把气泡节点或文本实现写成断言。
手动建造用招工木牌代表无居民开局的采木、搬运、施工、暂停与存档接续；建成后用同一交互用例验证费用设置、搬入金币和实际招募扣款。`/tmp/law3-input-player-build.png` 用于检查木牌详情及费用选择器，不另建单建筑展示脚本。
`/tmp/law3-input-blueprint-ready.png` 截取实际供料后、施工前的同一蓝图，人工检查建造图标气泡与缺料、建成状态的切换，不断言气泡节点或纹理。
`/tmp/law3-input-food-sites.png` 用于观察猎场、采集园和再生中的详情。用采集园代表野食建筑的原生蓝图放置、点击、手动生产及休整存档。
Linux X11 原生检查检测到 `/usr/bin/xdotool` 时使用系统鼠标按键，与真实指针保持一致；其他环境仍发送 Viewport 事件。检查时不要切换窗口或操作鼠标。
围挡施工与拆除后的通行保留在世界行为组，不按墙、栅栏、门重复建立同类输入用例。

交互组包含战术暂停的日历、居民与实物冻结、暂停中的原生拾取和零库存蓝图拖放、主动暂停与模态窗口组合、读档保留当前会话的暂停与速度、镜头变化不进入存档，以及 1×/2×/4× 实际运行时接线。仅这些检查短暂启用引擎模拟调度，其余行为仍直接推进有界模拟时间；输入驱动的长按与窗口等待使用真实时间，不受倍速影响。

固定 HUD 场景的存档、报告入口，以及默认工具快捷键和数字小键盘工资刷，复用同一交互组检查实际命令结果，不测试 InputMap、Theme 或 ButtonGroup 的通用引擎契约。

地图总览仍是按需的人工观察工具，不计入默认回归，也不检查种子、资源目录或各矿种点击：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-map-preview.log --path . --script tests/run.gd -- --generated-map --native
```

预览使用三个固定种子，输出 `/tmp/law3-generated-map-{seed}-{1440,960}.png` 和营地截图。

## 模块边界

| 文件 | 职责 |
| --- | --- |
| `run.gd` | 参数、启动、套件选择、汇总和退出 |
| `support/fixtures.gd` | 合法的初始地图、资源、设备和人口；不伪造执行中的活动 |
| `support/context.gd` | 断言、有界等待、报告与实物观察 |
| `support/viewport_input.gd` | 鼠标和键盘事件、窗口等待与代表性输入截图；不包含结果断言 |
| `world_behaviors.gd` | 零居民及无预建建筑的开局、起始点实物货币与双倍视野、木牌招募及入口阻挡/拆除/存档续接、缺料蓝图规划与实际供料、取消回收、私人财产隔离、居民不能直接采集野食、围挡通行、死亡后岗位释放、快照续接及坏档隔离 |
| `production_behaviors.gd` | 技能资格、单人稳定雇佣、蓝图建成后跨存档接续生产、0 工资关闭与续做结算、有限矿床、矿钻搬迁后的库存与存档、人工及传送带供料、原料与产品混存后的生产/存档/拆除回收、食物建筑选址与可重复产出、农田生长、畜棚只产羊毛、最后一点科研、市场货架与自动供料隔离、发电关闭 |
| `equipment_behaviors.gd` | 三类饮食、货币与食物分离、市场仅出售、库存和售价存档、途中改价与资金不足、银行食物借款、服务用品与污染载荷、个人装备 |
| `interaction_behaviors.gd` | 原生人物与建筑拾取、市场上架/撤货/售价/关闭、首座市场蓝图供料及建成拾取、搬迁后的新旧位置拾取和实物保留、拆除、HUD 拦截、失去视野后的统一遮蔽与不可交互、鼠标采掘供料施工、玩家与雇员接续同批生产、拖放取消与存档、手动上带和设施操作 |
| `diagnostics/map_preview.gd` | 按需地图总览，不执行内容验收 |

生产供料用同一组参数化用例覆盖人工交付和传送带：关闭储物箱岗位时，生产雇员不会越过劳动资格自行搬料；开放岗位后，两条线路都必须等到实际到货才能开工。消费和就医沿原有用例验证，不要求顾客拥有对应劳动能力。

套件不相互实例化；共享的起点、输入驱动和观察方法放在 support。
普通业务夹具可从已解锁科技的世界开始；科研夹具使用合法的前置和初始进度。夹具不代表出生规则或理想作息。

2026-11-10 转向后，旧版全员散矿、跨职业临时接单、面包即货币及个体直接供养不再是合法起点。四个原有行为组按新规则整理，不用兼容模式保留两套模拟，也不以修改执行中的雇佣、路径或劳动进度令用例通过。

## 不再承担的职责

- **全品类内容验收。** 不遍历全部建筑、产业、装备和矿种逐项运行完整模拟，也不为每条产业链另做一轮端到端验收。新增配置不自动增加测试；只有不同的执行机制或具体回归才增加案例。
- **平衡数值实验。** 不维护心情与装备的效率比较、污染暴露曲线、疲劳恢复、食堂恢复测量、增益倍率与持续时间实验，不把当前初版数值或自主活动倾向固化为测试合同。
- **展示验收。** 不检查飘字、缺料动画、效果提示、描述字段、图表排版、逐控件几何边界或素材图鉴。选中谁、命令是否生效、界面是否拦住世界输入仍属于交互契约。
- 不验证 Godot 的通用节点、信号、控件、排序或布局机制。
- 不把生活节奏、指定执行者、活动顺序、固定休息次数或生活达标当作通过条件；不反复调整需要、现金或心情来强迫预想选择。

## 保留的契约

1. **玩家命令。** 从合法起点下达实际命令，再推进有界游戏时间；不能通过改写活动、路径、任务进度或归属令任务完成。
2. **实物和付款。** 未到货不能消耗，未完成不能产出；运输、买卖与工资只转移所有权，消费和投入才减少库存。不能重复收费、透支、重复交付或丢失货物。
3. **取消与中断。** 只回收实际物资，不退还未满足的配方；保留已经结算的劳动，不重复发工资或复活已取消的指令。
4. **机制代表。** 普通建造代表缺料规划、实际供料与回收，加工代表已投入批次；矿床耗尽、生长、科研和死亡岗位释放各覆盖不同生命周期。放置按普通占地、矿床要求、水源限制和线状设施选代表，不按完整内容目录扩张。
5. **物理限制。** 保留完整占地、可达性、已预约运输、竞争接收、线路容量、断线和改接目的地的实际结果约束，不以简化测试为理由更改游戏中的这些保障。
6. **存档安全。** 按不同保存内容各取一个有意义的检查点，验证恢复不增减货物和款项、未完成命令可继续、已投入材料不重复扣除；重复恢复只验证一次，坏档不能替换当前世界或损坏健康备份。
7. **输入接线。** 使用真实 Viewport 事件验证选择、下单、取消、HUD 拦截和坐标重定位；同一条输入路径不按商品、工具、缩放和窗口尺寸做笛卡尔积。
8. **不掩盖失败。** 区分规则错误、无效夹具和越界预期，不为凑绿灯改变工人决策或删除仍在范围内的资金、物资安全检查。架构约束由代码审查保证。
