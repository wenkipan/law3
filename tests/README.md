# 测试标准

测试要回答“玩家做了什么，最后得到了什么”，而不是证明当前实现长什么样。
同样的玩法换一种实现，测试应该仍然成立。不要为了减少测试而改动游戏规则。

## 运行

日常只运行一个入口（失败返回非零退出码，并显示场景与失败结果）：

```sh
godot --headless --log-file /tmp/law3-tests.log --path . --script tests/run.gd
```

定位问题时可在末尾加 `-- --suite=world`，也可选择 `production`、`equipment`、`interaction`。
所有等待都有游戏时间上限，不依赖机器快慢，也不使用无限等待状态的循环。

修改交互或显示时，再跑同一套交互测试的窗口模式。期间不要移动鼠标：

```sh
godot --resolution 1440x900 --log-file /tmp/law3-native-tests.log --path . --script tests/run.gd -- --suite=interaction --native
```

窗口模式额外检查原生悬浮、鼠标不动时的遮挡变化，并输出
`/tmp/law3-behaviors-1440.png`、`/tmp/law3-behaviors-960.png`，以及相同尺寸的
`/tmp/law3-behaviors-bank-1440.png`、`/tmp/law3-behaviors-bank-960.png`。
每日报告默认和最小尺寸截图为 `/tmp/law3-behaviors-report-680.png`、`/tmp/law3-behaviors-report-560.png`。
矿道与货物截图为 `/tmp/law3-behaviors-belt-1440.png`、`/tmp/law3-behaviors-belt-960.png`，移动后的画面为 `/tmp/law3-behaviors-belt-moving.png`。
成排建筑预览与矿道转弯截图为 `/tmp/law3-behaviors-row-preview.png`、`/tmp/law3-behaviors-belt-corners.png`。
人工检查画面非空、素材正常、详情不遮挡、文字不截断、世界中只有工人姓名。
截图不是自动图像比对。

## 四组行为

| 文件 | 结果契约 |
| --- | --- |
| `world_behaviors.gd` | 采矿交付与取消；全部建筑一次扣料、退款、完成；矿道直接卸货、汇流、断线恢复、归属和运费；生活需求与床位；借款差额、还款和本金/利息收支；跨日报告、暂停、速度与重置 |
| `production_behaviors.gd` | 四类日产量跨天保留、停产与缺料；睡眠和午夜中断接续；原料竞争；打印有限订单和新人工作 |
| `equipment_behaviors.gd` | 交易不能超卖；卖出不补当日配额；矿枪确实更快、饮水确实减疲劳；背包双块交付、耗尽、半载返回 |
| `interaction_behaviors.gd` | 真实点击、缩放和遮挡；UI 拦截；蓝图完成后详情连续；全部建筑成排拖动、占地间距、轴向锁定与鼠标取消；矿道拖动、转弯、反向重连、拆除及载货保护；日产量控件、新人选择与窗口布局 |

`run.gd` 只负责启动、初始场景、有限等待、结果检查和输入事件，不替游戏实现生产或决策。

## 写法约定

1. **先安排起点，再操作，最后观察。** 初始资源、装备、疲劳、位置、已有建筑可以由夹具设置；操作必须走实际命令和模拟。不要直接写 `state`、`progress`、`owner`、路径或任务字典来制造中断、完成、交付。
2. **只断言有玩法含义的结果。** 库存、余额、产量、疲劳、使用次数、人数、报告、详情文字可以直接读取。它们虽存放在字典中，但代表玩家能观察的结果；并不要求所有逻辑测试都用鼠标操作。
3. **不锁定实现。** 不检查预算计算过程、调度状态名、任务归属、缓存命中、节点类型/身份、信号数量、贴图文件名。不直接调用 `assign_job`、`start_sleep` 等内部决策方法。入口是玩家命令、`simulate` 时钟或用于验证暂停/速度的引擎帧回调；UI 绑定和夹具允许知道少量结构，不能借辅助函数把实现断言藏起来。
4. **同一规则只维护一份。** 各类建筑共用扣料规则、各类生产共用日产量规则，用参数表覆盖差异。新品种优先加入现有表，不再复制整份测试和截图脚本。
5. **优先完整流程与关键失败路径。** 一项新规则通常补一个正常流程，加最有风险的边界，例如不足、取消、跨日、争抢或耗尽。不是每个分支都要一条测试；不以数量、行覆盖率或断言数作为目标。
6. **回归必须能说出玩家损失。** 例如“两个净水器把同一批水用了两次”，而非“任务 owner 错误”。新增回归尽量复用现有场景，保留能够区分正确与错误结果的断言。
7. **时间按业务结果等待。** 使用有上限的模拟时间等待交付、生产或购买；不要绑定某一帧的中间状态。只有规则本身涉及金额、时长或比例时才精确比较，并注明必要容差。
8. **界面测交互与可见内容。** 点击由 Viewport 分发，不用直接发按钮信号代替拾取测试。检查选中详情、控件禁用、布局边界，不要求具体节点树。不可用布局通过来替代人工画面检查。
